# Telemetry and Threat Analysis - Low-Interaction Web Honeypot

## 1. Files
| File | Purpose |
|---|---|
| app.py | FastAPI honeypot: fake .env / .git / wp-login / phpMyAdmin / admin portals, catch-all logger, writes to Supabase Postgres |
| schema.sql | Run once in Supabase SQL Editor to create the `events` table |
| render.yaml | Render blueprint (build/start command, env vars) |
| analyze.py | Pulls events from Supabase, GeoIP, MITRE mapping, charts, report tables |
| requirements.txt | Dependencies |

## 2. Set up Supabase
1. In your `telemetrytreathanalysis` project, open **SQL Editor -> New query**, paste `schema.sql`, Run.
2. Go to **Project Settings -> Database -> Connection string -> URI**. Use the **Session pooler**
   string (port 5432 on the *pooler* host), not the Direct connection (which is IPv6-only and won't work from Render). It looks like:
   `postgresql://postgres.<project-ref>:YOURPASSWORD@aws-0-eu-west-1.pooler.supabase.com:5432/postgres`
   Remove the [brackets] around the password; URL-encode symbols (@ -> %40, # -> %23).
3. Keep that string handy — it's your `DATABASE_URL`.

## 3. Run locally
    pip install -r requirements.txt
    export DATABASE_URL="postgresql://postgres.xxxx:[PASSWORD]@...pooler.supabase.com:5432/postgres"
    export EXPORT_TOKEN="pick-a-long-random-string"
    uvicorn app:app --port 8000 --no-server-header
    curl -i localhost:8000/.env
    curl -i -X POST localhost:8000/wp-login.php -d "username=admin&password=admin123"
    curl -H "X-Forwarded-For: 203.0.113.9" localhost:8000/.git/config   # check IP parsing
    curl localhost:8000/_export/$EXPORT_TOKEN | head        # confirm rows are landing in Supabase

## 4. Deploy on Render
1. Push this folder to a GitHub repo.
2. Render Dashboard -> New -> Blueprint (or Web Service) -> select repo.
3. Build: `pip install -r requirements.txt`  Start: `uvicorn app:app --host 0.0.0.0 --port $PORT --no-server-header`
4. Env vars: `DATABASE_URL` (the Supabase pooler string from step 2 above), `EXPORT_TOKEN` (auto-generated by
   render.yaml, or set your own), `MY_IPS` (your own IPs, comma-separated).
5. Note the public URL (https://<name>.onrender.com) and resolve its IP: `nslookup <name>.onrender.com`.
6. Verify IP handling: `curl https://<name>.onrender.com/.env` from your machine, then check the logged `ip`
   equals your real public IP (compare with https://ifconfig.me). You can see this either via `/_export/<token>`
   or directly in the Supabase **Table Editor -> events**.

## 5. Keep it alive 72-120 h
Render free instances sleep after ~15 min idle. Use an uptime pinger (UptimeRobot) hitting `/healthz` to keep
it awake — this doesn't touch the database, so it won't pollute your results. Since events live in Supabase,
not on Render's disk, a redeploy or restart no longer loses data. Render's Logs tab also keeps a readable
backup (lines start with `HP `), useful for screenshots.

## 6. Analyse
    export DATABASE_URL="postgresql://postgres.xxxx:[PASSWORD]@...pooler.supabase.com:5432/postgres"
    python analyze.py --exclude <your_ips>
Outputs `report_data.md`, `events_enriched.csv`, `charts/`.
